## 📐 Парадигма ExoKernel & DWG (High-Level System Design)

**ExoKernel** — это агностичная к базовому трансформеру архитектурная спецификация, разделяющая инференс языковой модели на два фундаментальных слоя: **Language Decoder Backbone (Core)** и **Dynamic Weight Graph (DWG)**.

> [!IMPORTANT]
> **Главный инженерный тезис ExoKernel:** Авторегрессионный декодер речи не должен хранить узкоспециализированные предметные пространства в своей весовой матрице.

### ⚙️ Модульные компоненты системы

#### 1. Decoupled Language Core (Замороженное ядро)

* **Функция:** Извлечение синтаксиса, удержание контекстного окна (Attention Context), форматирование ответа и авторегрессионный сэмплинг.
* **Инвариантность:** Ядро абстрагировано от конкретного бэкенда. В качестве Core может выступать любой декодер (от Llama/Qwen до кастомных файн-тюненных трансформеров). Веса ядра фиксируются (*Frozen*), исключая деградацию естественного языка (*Catastrophic Forgetting*).

#### 2. Dynamic Weight Graph (DWG)

* **Структура:** Ориентированный граф $G = (V, E)$, где вершина $v_i \in V$ представляет собой изолированный тензорный модуль (Domain Node), а ребро $e_{ij} \in E$ определяет коэффициент взаимной активации и синергии между доминами.
* **Механика маршрутизации:** На слое $L$ граф принимает скрытые состояния $h_l$ и высчитывает скалярные коэффициенты активации:

$$\alpha_i = \text{Softmax}(W_r \cdot h_l)$$

* **Weight Splicing (Тензорная инжекция):** Активированные вершины не заменяют слои трансформера, а выполняют динамическую проекцию в блоки Multi-Head Attention (к векторам Key/Value) или в межслойные активации Feed-Forward Networks (FFN):

$$h'_l = h_l + \sum_{i \in V_{\text{active}}} \alpha_i \cdot \phi_i(h_l)$$

#### 3. Domain Nodes (Автономные узлы графа)

* Каждый узел представляет собой компактную весовую структуру $W_{\text{node}} \in \mathbb{R}^{d \times k}$, обученную строго на представлении конкретного домена (синтаксис C++, системные вызовы POSIX, формальная логика).
* Узлы модульны и вычуждаемы: их можно *hot-swap*’ить (горячая замена в RAM/VRAM) без перезагрузки инференс-пайплайна самого Core.

### 🔬 Строгий сравнительный анализ для Machine Learning Engineers

| Инженерный критерий | Monolithic Dense Transformer | Mixture of Experts (MoE) | PEFT / LoRA Ensembles | **ExoKernel + DWG Architecture** |
| :--- | :--- | :--- | :--- | :--- |
| **Вычислительная гранула** | Единый тензор параметров $\Theta$ | Фиксированные внутрислойные FFN-эксперты | Статические матрицы $A \times B$ низкого ранга | **Графовая топология внешних тензорных узлов** |
| **Формирование графа вычислений** | Статичное ($O(1)$ по топологии) | Динамический Top-K Softmax на каждом токене | Статичное для рабочей сессии | **Динамическое подграф-сэмплирование (Sub-graph Routing)** |
| **Аллокация VRAM** | $O(\Theta)$ — весь объем весов в памяти | $O(E \times \text{Size}_{\text{FFN}})$ — требовательно к памяти | $O(N_{\text{base}} + \sum \text{LoRA})$ | **$O(\text{Core}) + O(G_{\text{active}})$ — линейная оптимизация** |
| **Inter-Domain Synergy (Смешивание)** | Неуправляемый сдвиг гиперплоскости | Ограничено линейной комбинацией Top-K | Требует математического мерджа ($W + BA$) | **Смешивание через взвешенные ребра $e_{ij}$ графа DWG** |
| **Модульность и Hot-Swapping** | Отсутствует | Отсутствует (требует полной сборки) | Частично (высокий cost на переключение) | **Нативная поддержка на уровне администрирования графа** |

### 🛠️ Инструкция для разработчиков (Как запустить и протестировать)

<details>
<summary><b>Нажмите, чтобы развернуть подробный гайд</b></summary>

1. **Подготовка системы:** Убедитесь, что у вас установлен Python версии 3.10 или выше, а также `git`.
2. **Клонирование:**
   ```bash
   git clone [https://github.com/YOUR_USERNAME/exokernel.git](https://github.com/YOUR_USERNAME/exokernel.git)
   cd exokernel
   ```
    Настройка изолированного окружения:
    ```Bash

      python3 -m venv venv
      source venv/bin/activate  # На Linux / macOS
      # или venv\Scripts\activate для Windows
    ```
Установка библиотек:
```Bash

pip install -r requirements.txt
```
Запуск чат-интерфейса:
```Bash

python3 chat.py
```
При первом запуске скрипт автоматически скачает веса разговорного ядра. На устройствах с поддержкой CUDA модель запустится на GPU, иначе переключится на CPU. </details>
Проект находится в стадии активной разработки. Pull Request'ы и идеи по улучшению архитектуры приветствуются!
