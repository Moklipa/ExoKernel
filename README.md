## 💡 Основы и концепция

Традиционные LLM пытаются вместить все знания мира в единый монолитный массив весов. `ExoKernel` предлагает принципиально иной, модульный подход:

| Традиционный подход (Monolithic LLM) | Подход ExoKernel (Split-Kernel Architecture) |
| :--- | :--- |
| ❌ Требует десятки гигабайт VRAM | ✅ Работает даже на GPU с 2 ГБ VRAM |
| ❌ Переобучение затрагивает всю модель | ✅ Домены подключаются и обновляются независимо |
| ❌ Скорость генерации падает с ростом весов | ✅ Разговорное ядро всегда остаётся лёгким |

## 🏗️ Архитектура системы

```text
                     ┌───────────────────────────┐
                     │        User Input         │
                     └─────────────┬─────────────┘
                                   │
                                   ▼
                   ┌───────────────────────────────┐
                   │        ExoKernel Core         │
                   │   (Instruct / Conversation)   │
                   └───────────────┬───────────────┘
                                   │
                                   ▼
                   ┌───────────────────────────────┐
                   │  Dynamic Weight Graph (DWG)   │
                   │   (Graph Routing & Splicing)  │
                   └───────────────┬───────────────┘
                                   │
       ┌───────────────────────────┼───────────────────────────┐
       ▼                           ▼                           ▼
┌──────────────┐            ┌──────────────┐            ┌──────────────┐
│ Domain Node  │            │ Domain Node  │            │ Domain Node  │
│  (Code Engine)│           │ (SysAdmin)   │            │  (Math Logic)│
└──────────────┘            └──────────────┘            └──────────────┘
```

  
   Как это работает:

   Core (Разговорное ядро): Удерживает контекст беседы, отвечает за диалоговый синтаксис и понимание намерений пользователя.

   Dynamic Splicer: Оценивает эмбеддинги запроса и "на лету" подмешивает токены/представления нужного домена.

   Domain Engines: Автономные легковесные модули (программирование, системные команды Linux, математика).

Главное отличие **ExoKernel** от классических подходeв (MoE или LoRA) — использование **Динамического Графа Весов (DWG)**.

В стандартных сетях связки весов статичны. В ExoKernel базовое ядро слушает поток контекста и активирует узлы графа DWG во время инференса.

> [!IMPORTANT]
> **Принцип работы Dynamic Weight Graph:**
> 1. **Core Backbone:** Разговорное ядро генерирует первичные контекстные эмбеддинги.
> 2. **DWG Routing (Маршрутизация по графу):** В зависимости от намерений пользователя активируются соответствующие вершины и ребра графа DWG (Domain Nodes).
> 3. **Weight Splicing (Сплайсинг весов):** Подключенные узлы графа модулируют параметры внимания (Attention Keys/Values) ядра, направляя его в узкую предметную область без загрузки монолитных тяжелых моделей.

---

### Сравнительный анализ: DWG vs Монолит vs MoE vs LoRA

| Параметр | Монолит (Dense) | MoE (Mixture of Experts) | LoRA / PEFT | **ExoKernel (DWG)** |
| :--- | :--- | :--- | :--- | :--- |
| **Структура знаний** | Единая статическая матрица | Набор тяжелых экспертов в памяти | Фиксированная весовая накладка | **Динамический граф узлов (Nodes)** |
| **Потребление VRAM** | Высокое | Очень высокое | Низкое | **Минимальное (2 ГБ VRAM + граф)** |
| **Масштабируемость** | Переобучение всей сети | Сложная балансировка маршрутизатора | Переключение между адаптерами | **Изолированное добавление узлов в DWG** |
| **Сохранение речи** | Есть риск деградации | Зависит от обучения | Минимальный риск | **Полное разделение разговорного ядра и графа** |
